# 保存地图上的 EGO 离线点击规划

```bash
ego-map-demo
ego-map-demo --goal 0 4
ego-map-demo --stop
```

窗口工具栏 **2D Nav Goal**：在地图上按下并短拖鼠标选择目标。
每次都从建图原点规划，起终点高度是原点附近地面以上约1.5m（地图z=1.34461m）。
绿色球是虚拟起点，橙色球是目标，绿色曲线是 EGO 优化后实际采样的 B 样条。
灰色点云为保存地图；蓝色方格是规划器在当前高度上实际使用的膨胀障碍区域。
点击障碍内、范围外或规划失败时清除旧路径，不显示伪造成功结果。
这是静态地图上的局部EGO优化演示；跨越长墙或需要很远绕行的目标可能失败，不保证全地图任意两点都有解。

输入为今天地图 `20261105_114605_outdoor/map_world.pcd`。
全部原始点用于静态占据体素（有效范围x/y各±64m，z=-0.5～4m），分辨率0.2m。
占据体素按半径0.4m、半高0.25m加体素余量保守膨胀；额外高度约束使曲线保持在
原点附近地面以上约1.5m（高度波动不超过约0.25m），不通过大幅爬升越过障碍。
PCD未占据的位置按静态演示的空闲空间近似，不提供实机的未知空间/动态障碍证明。
这里不运行项目实机导航适配器、执行器或 MAVROS，不代表飞行验收。

算法来自官方固定版本 `ZJU-FAST-Lab/ego-planner-swarm@92fe9f7227b2da819133eb8e0e8c7fc000f6ae20`，
直接调用 `EGOPlannerManager::reboundReplan`，包含原版 A* 引导、B样条优化、时间重分配。
官方源码在 `official/`。构建时去掉管理器头文件中未使用的 DataDisp 消息头引用，
并把旧版头文件中超出int范围的默认迭代上限1e10修正为INT_MAX；优化流程沿用官方实现。
显示成功前对采样曲线与相邻采样间的线段逐段检查膨胀栅格，并核对起终点。

独立 Docker 容器 **--network none**，只有容器内 Master，无法连接板端飞控或实机 ROS。
主机仅挂载只读地图、X11和独立的结果/布局目录。关闭窗口时一起结束本容器内节点。
当前结果记录在 `results/latest.json` 和 `results/path.csv`。

源码保存在板端 `/home/orangepi/orange/tools/ego_map_demo`，本机安装在
`~/.local/share/ego-swarm-map-demo`，不构建或修改本机独立 ROS 仓库。
